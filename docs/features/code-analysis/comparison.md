# Code Analysis — Comparison

## Overview

Comparisonは、2つのソースコードの解析結果を比較し、コードの規模・複雑性・結合度・凝集度・重複などの違いを確認するための機能です。

リファクタリング前後の変化や、異なる実装の特性を定量的に比較できます。

比較は解析対象全体の集計値を使用して行います。ファイル構成や関数・クラスの名前が異なっていても比較できます。

Comparisonは計測値の差異を明らかにする機能であり、コード品質の改善・悪化や優劣を自動的に判定するものではありません。

## Comparison Targets

Comparisonでは、以下の2種類の入力をサポートします。

| 入力 | 説明 |
|---|---|
| Source Code | ファイルまたはディレクトリを指定し、解析した結果を比較する |
| Analysis Result | 保存済みの解析結果を読み込み、比較する |

比較元を**Before**、比較先を**After**として扱います。

### Source Code

2つのファイルまたはディレクトリを指定して比較できます。

```bash
cqa compare ./before ./after
cqa compare ./implementation_a.py ./implementation_b.py
```

ファイルとディレクトリを組み合わせることもできます。

```bash
cqa compare ./implementation_a.py ./implementation_b
```

それぞれを独立して解析し、取得した計測結果を比較します。

解析対象の選択規則とエラー処理は[Targets](./targets.md)に従います。

### Analysis Result

保存済みの解析結果を比較できます。

- ソースコードを再解析せずに比較します。
- 解析元のソースコードが存在しなくても比較できます。
- 保存された計測値と計測条件を使用します。
- 計測条件の互換性を確認します。
- 必要な情報が不足している場合は、該当する比較項目を比較不能として扱います。

保存済み解析結果は、[Output](./output.md)で定義する機械可読な形式に従います。

ソースコードと保存済み解析結果を組み合わせる場合も、それぞれから得られた解析結果を使用して比較します。

### Comparison Scope

比較単位は**Analysis Scope（解析範囲）**とします。

Analysis Scopeは、指定したファイルまたはディレクトリから選択された解析対象全体を意味します。

例えば、次のように構成が異なる場合です。

```text
before/
├── service.py
└── repository.py

after/
├── application.py
├── domain.py
└── infrastructure.py
```

それぞれの解析対象全体の集計値を比較します。

- ファイル同士の対応付けは行いません。
- 関数・クラス同士の対応付けは行いません。
- ファイルの追加・削除・移動は個別に判定しません。
- ディレクトリ構造が異なっていても比較できます。
- 解析対象の規模の違いは、対応する計測指標の差分として表現します。

## Comparison Metrics

Comparisonでは、[Metrics](./metrics/README.md)で定義された計測指標を使用します。

比較対象となるのは、Analysis Scope単位で提供される集計値です。

| 指標 | 比較する値 |
|---|---|
| SLOC | Total |
| Function Length | Average、Maximum |
| Function Count | Total |
| Class Count | Total |
| Cyclomatic Complexity | Total、Average、Maximum |
| Cognitive Complexity | Total、Average、Maximum |
| Nesting Depth | Average、Maximum |
| CBO | Average、Maximum |
| Fan-out | Average、Maximum |
| Dependency Cycles | 循環依存グループ数 |
| LCOM4 | Average、Maximum |
| Duplication Rate | 解析対象全体の重複率 |

同じ指標でも、Total、Average、Maximumはそれぞれ独立した比較項目として扱います。

新しい指標が追加された場合も、比較可能な数値と集計方法が定義されていれば、同じ比較規則を適用します。

比較対象となる値が存在しない場合や計測条件に互換性がない場合は、該当する項目の差分を算出しません。

## Difference Calculation

各比較項目について、以下の情報を提供します。

| 項目 | 説明 |
|---|---|
| Before | 比較元の計測値 |
| After | 比較先の計測値 |
| Difference | 符号付き差分 |
| Change Rate | 比較元を基準とした変化率 |

### Difference

差分は、AfterからBeforeを引いて算出します。

```text
Difference = After - Before
```

- 正の値は増加を表します。
- 負の値は減少を表します。
- 0は変化がないことを表します。

### Change Rate

変化率は、Beforeを基準として算出します。

```text
Change Rate = (After - Before) / Before × 100
```

変化率の単位はパーセント（%）です。

Beforeが0の場合、変化率は`null`とし、算出できない理由を記録します。

BeforeとAfterがともに0の場合も同様です。

### Percentage Metrics

Duplication Rateなど、計測値自体がパーセントである指標についても同じ計算規則を適用します。

ただし、Differenceの単位はパーセントポイント（pt）とします。

例えば、Duplication Rateが15%から10%に変化した場合です。

```text
Before      = 15%
After       = 10%
Difference  = -5pt
Change Rate = -33.333...%
```

DifferenceとChange Rateは異なる意味を持つため、区別して提供します。

### Numerical Precision

差分と変化率は、計測結果が保持する数値の精度を使用して算出します。

- 計算途中で表示用の丸め処理を行いません。
- 表示時の丸め方は出力形式ごとに定義します。
- 表示された数値を再利用して差分を計算しません。
- 数値の精度が異なることだけを理由に、比較不能とは扱いません。

## Comparison Results

比較結果には、少なくとも以下の情報を含めます。

- 比較元と比較先の解析対象情報
- 比較元と比較先の計測結果
- 比較可能な指標のDifferenceとChange Rate
- 比較できなかった指標とその理由
- 解析の失敗や未解決情報
- 計測条件と比較条件
- 結果が完全か、部分的なものかを判断できる情報

具体的なデータ構造や表示形式は[Output](./output.md)で定義します。

### Example

以下は、リファクタリング前後の比較例です。

| 指標 | Before | After | Difference | Change Rate |
|---|---:|---:|---:|---:|
| SLOC | 200 | 180 | -20 | -10% |
| Function Count | 10 | 12 | +2 | +20% |
| Cyclomatic Complexity（Average） | 5 | 3 | -2 | -40% |
| Nesting Depth（Maximum） | 4 | 2 | -2 | -50% |
| CBO（Average） | 2 | 3 | +1 | +50% |
| Duplication Rate | 15% | 10% | -5pt | -33.33…% |

この結果から、AfterではSLOCや平均Cyclomatic Complexityが減少した一方、Function Countや平均CBOが増加したことが分かります。

ただし、これらの数値の変化だけでコード品質の改善・悪化を判断しません。

## Measurement Compatibility

異なる解析結果を比較する場合、計測条件の互換性を確認します。

同じ指標であっても、計算規則や計測対象が異なる場合、単純な差分には意味がない可能性があります。

### Compatibility Rules

以下の条件を満たす場合、比較可能とします。

- 同じ指標を計測している。
- 同じ集計方法の値を比較している。
- 計測値の定義と計算規則に互換性がある。
- 計測結果に影響する設定が互換である。
- 計測値の単位が一致する、または互換な単位へ換算できる。

計測モデルやツールのバージョンが異なっていても、計算規則の互換性が確認できれば比較できます。

一方、バージョンが同じでも、計測結果に影響する設定が異なる場合は比較不能となることがあります。

互換性を確認できない場合は、比較可能と推測せず、該当する指標を比較不能として扱います。

### Compatibility Examples

| 条件 | 取り扱い |
|---|---|
| 同じ計測モデル・同じ設定 | 比較可能 |
| ツールのバージョンだけが異なり、計算規則は同じ | 比較可能 |
| Cyclomatic Complexityの計数規則が異なる | 比較不能 |
| Duplication Rateの最小一致トークン数が異なる | 比較不能 |
| 同じ指標だが集計方法が異なる | 比較不能 |
| ファイル数やディレクトリ構造が異なる | 比較可能 |
| 解析対象の除外設定が異なる | 比較可能。ただし解析範囲の違いを確認できるようにする |

互換性は指標ごとに判断します。

一部の指標に互換性がなくても、ほかの比較可能な指標については処理を継続します。

保存済み解析結果についても同じ互換性規則を適用します。

## Unavailable Metrics

比較元または比較先の計測値が`null`の場合、DifferenceとChange Rateも`null`とします。

`null`を0に置き換えて計算することはありません。

| Before | After | Difference | Change Rate |
|---:|---:|---:|---:|
| 10 | 5 | -5 | -50% |
| 0 | 5 | +5 | `null` |
| 5 | 0 | -5 | -100% |
| 0 | 0 | 0 | `null` |
| `null` | 5 | `null` | `null` |
| 5 | `null` | `null` | `null` |
| `null` | `null` | `null` | `null` |

計測不能な理由は比較結果にも保持します。

### Missing Metrics

比較元と比較先で取得できる指標が異なる場合、共通して存在する比較可能な指標について差分を算出します。

片方にしか存在しない指標は比較不能として扱い、その理由を記録します。

### No Comparable Metrics

比較可能な指標が1つも存在しない場合、空の比較結果を返します。

- 比較可能な項目数を0件とします。
- 比較できなかった理由を記録します。
- Comparison自体は正常終了とします。
- 比較元と比較先の解析情報は保持します。

ただし、入力データの形式が不正であるなど、解析結果として読み込めない場合は、空の比較結果ではなく入力エラーとして扱います。

## Partial Analysis

一部のファイルで構文エラーや読み取りエラーが発生した場合でも、正常に解析できたファイルの計測結果を保持します。

Comparisonでは、部分的な解析結果を使用した比較を許可します。

- 取得できた計測値についてDifferenceとChange Rateを算出します。
- 解析に失敗したファイルの情報を保持します。
- 比較結果が部分的なものであることを明示します。
- 完全な解析結果との比較も許可します。

例えば、Beforeが100ファイルすべての解析に成功し、Afterが80ファイルのみ成功した場合でも、取得した計測値の比較は行います。

ただし、その差分がコードそのものの変更だけによるものとは限りません。

### Unresolved Dependencies

CBOやFan-outなどで依存先の一部を特定できなかった場合は、確定した計測値を使用して比較します。

- 未解決の依存関係を0件とはみなしません。
- 確定した依存関係の計測値を使用します。
- BeforeとAfterそれぞれの未解決情報を保持します。
- 不完全な計測値に基づく比較であることを明示します。

例えば、以下のような場合です。

| 項目 | Before | After |
|---|---:|---:|
| CBO | 3 | 2 |
| 未解決参照 | 0 | 5 |

Differenceは`-1`ですが、Afterには未解決参照が存在します。

そのため、この差分は確定した依存関係に基づくものであり、実際の結合度が1減少したことを保証しません。

## Boundary Cases

以下は、Comparisonで扱う代表的な境界条件です。

| ケース | 期待される動作 |
|---|---|
| 同じソースコード・同じ計測条件 | 再現可能な計測値の差分は0 |
| 同じソースコード・異なる計測条件 | 互換性を確認して比較 |
| ファイル同士を比較 | 比較可能 |
| ディレクトリ同士を比較 | 比較可能 |
| ファイルとディレクトリを比較 | 比較可能 |
| 保存済み解析結果同士を比較 | 比較可能 |
| ソースコードと保存済み解析結果を比較 | 比較可能 |
| 解析元のソースコードが存在しない保存済み結果 | 保存済みの情報で比較 |
| ファイル構成が異なる | Analysis Scope単位で比較 |
| 関数名・クラス名が異なる | 個別の対応付けは行わない |
| 計測値が増加 | 正のDifference |
| 計測値が減少 | 負のDifference |
| 計測値が同じ | Differenceは0 |
| Beforeが0 | Change Rateは`null` |
| BeforeまたはAfterが`null` | Difference・Change Rateは`null` |
| 片方にしか存在しない指標 | 比較不能として理由を記録 |
| 計測条件に互換性がない | 対象指標の差分を算出しない |
| 互換性を確認できない | 対象指標を比較不能とする |
| 比較可能な指標が0件 | 空の比較結果を返し、正常終了 |
| 一部のファイルで解析失敗 | 取得できた値を比較し、部分的な結果であることを明示 |
| 未解決の依存関係が存在 | 確定した値を比較し、未解決情報を保持 |
| 解析対象が0件 | Metricsの空結果の規則に従って比較 |
| 比較対象のパスが存在しない | Targetsのエラー処理に従う |
| 保存済み解析結果が不正 | 入力エラーとして扱う |

## Limitations

- Comparisonは解析対象全体の計測値を比較するものであり、個々のファイル・関数・クラスの変更箇所を特定するものではありません。
- ファイルの追加・削除・移動や、関数・クラスの名称変更を検出しません。
- 計測値の増減だけで、コード品質の改善・悪化を判定することはできません。
- 解析対象の規模が異なる場合、合計値の差は対象規模の影響を受けます。
- 平均値や最大値が一致していても、個々の計測値の分布が同じとは限りません。
- 部分的な解析結果を含む比較は、解析対象全体の完全な差分を保証しません。
- 未解決の依存関係がある場合、確定した依存数の差分が実際の依存関係の増減を表すとは限りません。
- 計測モデルや設定の互換性を確認できない指標は、比較対象外とします。
