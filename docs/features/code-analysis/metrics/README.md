# Code Analysis — Metrics

## Overview

Code Analysisでは、Pythonのソースコードを対象に、コードの規模、複雑性、結合度、凝集度、重複を定量的に計測します。

これらの指標を使用することで、コードの特徴を把握し、異なる実装や変更前後のコードを比較できます。

各指標は、関数・クラス・ファイルなど、指標の性質に適した単位で計測します。また、ファイルや解析対象全体の集計結果も提供するため、個別の問題箇所とコード全体の傾向を確認できます。

## Available Metrics

Code Analysisでは、以下の5カテゴリの指標を提供します。

| カテゴリ | 指標 | 評価する内容 |
|---|---|---|
| [Size](./size.md) | SLOC、Function Length、Function Count、Class Count | コードの規模や構成 |
| [Complexity](./complexity.md) | Cyclomatic Complexity、Cognitive Complexity、Nesting Depth | 制御フローの複雑さや理解のしやすさ |
| [Coupling](./coupling.md) | CBO、Fan-out、Dependency Cycles | クラスやモジュール間の依存関係 |
| [Cohesion](./cohesion.md) | LCOM4 | クラス内のメソッド間の結び付き |
| [Duplication](./duplication.md) | Duplication Rate | コードの重複状況 |

各指標の計測方法、計算規則、境界条件については、カテゴリごとのドキュメントを参照してください。

## Measurement Levels

計測結果は、以下の4つの単位で扱います。

| 単位 | 説明 |
|---|---|
| Function | 個々の関数・メソッド |
| Class | 個々のクラス |
| File | 個々のPythonソースファイル |
| Project | 指定した解析対象全体 |

指標によって、直接計測できる単位は異なります。

例えば、Cyclomatic Complexityは関数単位で計測しますが、ファイル単位ではそのファイルに含まれる関数の平均値や最大値を確認できます。

一方、Dependency Cyclesはモジュール間の依存関係を調べるため、解析対象全体を対象に検出します。

### Measurement Matrix

以下の表は、各指標をどの単位で取得できるかを示します。

| 指標 | Function | Class | File | Project |
|---|:---:|:---:|:---:|:---:|
| SLOC | — | — | ◎ | ○ |
| Function Length | ◎ | ○ | ○ | ○ |
| Function Count | — | ○ | ◎ | ○ |
| Class Count | — | — | ◎ | ○ |
| Cyclomatic Complexity | ◎ | ○ | ○ | ○ |
| Cognitive Complexity | ◎ | ○ | ○ | ○ |
| Nesting Depth | ◎ | ○ | ○ | ○ |
| CBO | — | ◎ | ○ | ○ |
| Fan-out | — | — | ◎ | ○ |
| Dependency Cycles | — | — | — | ◎ |
| LCOM4 | — | ◎ | ○ | ○ |
| Duplication Rate | — | — | ○ | ◎ |

- **◎**：指標を直接計測する単位
- **○**：集計値または対象範囲から算出した値を提供する単位
- **—**：対象外

Projectは、解析対象に指定したファイルまたはディレクトリ全体を表します。

## Aggregation

関数やクラスなどの個別の計測値は、上位の単位で集計できます。

例えば、あるファイルに3つの関数があり、それぞれのCyclomatic Complexityが3、5、10だった場合、ファイル全体の結果は次のようになります。

| 集計項目 | 値 |
|---|---:|
| Total | 18 |
| Average | 6 |
| Maximum | 10 |

このように、個別の関数の複雑さだけでなく、ファイル全体の傾向や、複雑さが集中している箇所を確認できます。

集計では、指標の性質に応じて以下を使用します。

- **Total**：計測値の合計
- **Average**：計測値の算術平均
- **Maximum**：計測値の最大値

すべての指標に3種類の集計を適用するわけではありません。例えば、SLOCは合計を使用し、Function Lengthは平均と最大を使用します。

また、Duplication Rateのような割合の指標は、個別の割合を平均するのではなく、対象範囲のコード量と重複量から算出します。

集計後も、個々の関数やクラスの計測結果を確認できます。

## Empty and Unavailable Results

計測結果が0の場合と、計測できなかった場合は区別します。

例えば、クラスが存在しないファイルのClass Countは`0`ですが、関数が存在しないファイルの平均Cyclomatic Complexityは算出できないため、`null`となります。

共通の取り扱いは以下のとおりです。

| 状態 | 結果 |
|---|---|
| 計数・合計の対象が存在しない | `0` |
| 平均・最大の対象が存在しない | `null` |
| 正常に計測した結果が0 | `0` |
| 計測できない | `null`と理由 |
| 一部の情報を特定できない | 確定した値と未解決情報を区別 |

一部のファイルで構文エラーや読み取りエラーが発生した場合は、正常に解析できたファイルの結果を集計し、部分的な解析結果であることを示します。

個別指標の計測不能条件については、各カテゴリのドキュメントで定義します。

## Reproducibility

異なる実装や変更前後のコードを適切に比較するためには、同じ計測条件で解析する必要があります。

そのため、計測結果には以下の情報を記録します。

- 解析ツールのバージョン
- 計測モデルとそのバージョン
- 計測設定
- 解析対象の情報
- 計測上の制約や未解決情報

計測モデルや設定が異なる場合は、同じ指標名であっても結果が一致するとは限りません。

## Interpreting Results

各指標は、コードの特定の性質を表しています。

例えば、Cyclomatic Complexityが低くても、外部のクラスへの依存が多い場合があります。また、SLOCが少なくても、制御フローが複雑な場合があります。

そのため、単一の数値だけでコード品質の良し悪しを判断するのではなく、複数の指標を組み合わせて評価します。

指標の具体的な計測規則や制約については、各カテゴリのドキュメントを参照してください。
