# Cohesion Metrics

## Overview

Cohesion Metricsは、クラス内のメソッドがどの程度関連し、一つのまとまった責務を構成しているかを評価するための指標です。

クラス内のメソッドが共通のインスタンス属性を使用しているか、互いに呼び出し合っているかを分析することで、責務が分散している可能性のあるクラスを確認できます。

以下の指標を提供します。

| 指標 | 説明 | 基本計測単位 |
|---|---|---|
| LCOM4 | メソッド間の結び付きの弱さを接続グループ数で表す | Class |

計測単位や集計に関する共通ルールは[Metrics](./README.md)を参照してください。

## LCOM4

### Definition

LCOM4（Lack of Cohesion in Methods 4）は、クラス内のメソッド間の結び付きを、接続グループの数として表す指標です。

2つのメソッドが次のいずれかの条件を満たす場合、関連していると判定します。

- 同じインスタンス属性を参照している。
- 一方のメソッドが他方のメソッドを呼び出している。

これらの関係をたどることで、直接つながっていないメソッド同士も同じグループに属する場合があります。

LCOM4は、このように形成される独立したグループの数を計測します。

一般に、値が1であれば対象メソッドが一つのグループにつながっており、2以上であれば複数のグループに分かれていることを示します。

ただし、LCOM4だけでクラスの責務が適切かどうかを断定することはできません。

### Measurement Rules

LCOM4は、クラス単位で計測します。

#### 対象メソッド

クラス内で直接定義されたインスタンスメソッドを計測対象とします。

| メソッド | 取り扱い |
|---|---|
| 通常のインスタンスメソッド | 含める |
| `async def`によるインスタンスメソッド | 含める |
| `__init__` | 除外する |
| `@property`のgetter | 含める |
| `@property`のsetter / deleter | 含める |
| `@staticmethod` | 除外する |
| `@classmethod` | 除外する |
| その他の特殊なインスタンスメソッド | 含める |
| 継承されたメソッド | 除外する |

デコレータが付いているだけの通常のインスタンスメソッドは、原則として計測対象に含めます。

`@property`のgetter、setter、deleterは、それぞれ独立したメソッドとして扱います。

#### インスタンス属性による関連付け

2つのメソッドが同じインスタンス属性を参照している場合、関連していると判定します。

- `self.name`など、インスタンス属性への読み取り・書き込みを対象とします。
- 同じ属性を複数回参照しても、関連付けは1つとして扱います。
- 異なる属性名は別の属性として扱います。
- クラス属性やローカル変数の共有は、インスタンス属性の共有として扱いません。
- `__init__`はLCOM4の対象メソッドから除外します。ただし、そこで定義されたインスタンス属性を、ほかのメソッドが参照する場合は計測できます。
- 継承元で定義された属性も、対象メソッドから静的に参照を確認できる場合は対象とします。

属性名を実行時に組み立てるなど、静的に属性を特定できない場合は、関連付けに使用しません。

#### メソッド呼び出しによる関連付け

対象メソッド間の呼び出し関係も関連付けの対象とします。

- `self.method()`など、同一クラス内の対象メソッドへの呼び出しを対象とします。
- 呼び出し方向は区別せず、いずれか一方向の呼び出しがあれば関連していると判定します。
- 同じメソッドを複数回呼び出しても、関連付けは1つとして扱います。
- 自分自身への再帰呼び出しは、新しい関連付けを追加しません。
- 継承メソッドへの呼び出しは、対象メソッド間の関連付けに含めません。
- 呼び出し先を静的に特定できない場合は、関連付けに使用しません。

#### 接続グループの計数

関連付けされたメソッドを一つのグループとして扱います。

- 直接または間接的につながっているメソッドは、同じグループに属します。
- ほかのメソッドと関連がないメソッドも、単独のグループとして計数します。
- 同じグループ内に複数の関連付けが存在しても、グループ数は増加しません。
- グループの数をLCOM4の計測値とします。

### Boundary Cases

| ケース | 期待される動作 |
|---|---|
| 対象メソッドが0件 | `null` |
| 対象メソッドが1件 | `1` |
| 2つのメソッドが同じ属性を参照 | `1` |
| 2つのメソッドが異なる属性のみを参照 | `2` |
| 2つのメソッド間に呼び出し関係がある | `1` |
| 3つのメソッドが間接的につながる | `1` |
| 2つの独立したメソッドグループがある | `2` |
| 属性を参照しないメソッドが1つ存在 | ほかとの呼び出し関係がなければ独立した1グループ |
| 同じ属性を複数回参照 | グループ数に影響しない |
| 同じメソッドを複数回呼び出し | グループ数に影響しない |
| 自分自身への再帰呼び出し | グループ数に影響しない |
| `__init__`のみのクラス | `null` |
| `@staticmethod`のみのクラス | `null` |
| `@classmethod`のみのクラス | `null` |
| 継承メソッドのみを持つクラス | `null` |
| クラスが存在しない | 平均・最大は`null` |

### Examples

#### Example 1: 属性を共有するメソッド

```python
class Counter:
    def __init__(self):
        self.value = 0

    def increment(self):
        self.value += 1

    def reset(self):
        self.value = 0
```

計測結果：

`LCOM4 = 1`

`increment()`と`reset()`が共通の`self.value`を使用しているため、同じグループに属します。

`__init__()`は対象メソッドに含めません。

#### Example 2: 独立したメソッド

```python
class Service:
    def process_users(self):
        self.users = []

    def process_orders(self):
        self.orders = []
```

計測結果：

`LCOM4 = 2`

2つのメソッドは異なるインスタンス属性を使用し、互いに呼び出していません。

そのため、独立した2つのグループとして計数します。

#### Example 3: メソッド呼び出しによる関連付け

```python
class Service:
    def execute(self):
        self.validate()

    def validate(self):
        self.check()

    def check(self):
        pass
```

計測結果：

`LCOM4 = 1`

`execute()`から`validate()`、`validate()`から`check()`への呼び出し関係があります。

3つのメソッドは間接的につながるため、一つのグループとして扱います。

#### Example 4: 対象メソッドが存在しない場合

```python
class Config:
    def __init__(self):
        self.value = 10

    @staticmethod
    def default():
        return 10
```

計測結果：

`LCOM4 = null`

`__init__()`と`@staticmethod`は計測対象外であるため、対象メソッドが存在しません。

### Aggregation

LCOM4は、クラス単位の計測結果をファイルおよび解析対象全体で集計します。

| 集計方法 | 説明 |
|---|---|
| Average | 計測可能なクラスのLCOM4の算術平均 |
| Maximum | 計測可能なクラスのLCOM4の最大値 |

LCOM4が`null`のクラスは、平均値・最大値の計算に含めません。

計測可能なクラスが存在しない場合、平均値・最大値は`null`とします。

集計後も、各クラスのLCOM4を取得できます。

共通の集計ルールは[Metrics — Aggregation](./README.md#aggregation)を参照してください。

### Limitations

- LCOM4はメソッド間の構造的な関連性を計測するものであり、クラスの責務や設計の妥当性を直接判定するものではありません。
- インスタンス属性を使用しないユーティリティ的なクラスでは、LCOM4が高くなる場合があります。
- `__init__`などの対象外メソッドを介した間接的な関連性は計測しません。
- 動的属性アクセスや実行時に変更されるメソッドの関係は、静的に確認できる範囲でのみ評価します。
- デコレータによるメソッドの振る舞いの変更は、実行時の効果まで解析するものではありません。
- 本仕様の特殊メソッドの除外規則は、LCOM4の唯一の標準ではなく、Code Analysis固有の計測規則です。
