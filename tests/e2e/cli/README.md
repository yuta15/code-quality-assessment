# CLI E2Eテストケース

## 目的と前提

利用者が起動する`cqa`コマンドを別プロセスで実行し、外部仕様への適合性を検証する。
仕様のSingle Source of Truthは[Code Analysis](../../../docs/features/code-analysis/README.md)とする。
このREADMEはテスト設計であり、新たなオプションやエラー仕様を定義しない。

- 入力はコマンド引数、実際のソースファイル・ディレクトリ、保存済みJSON、実行環境とする。
- 観測対象は終了コード・stdout・stderr・保存結果・入力ファイルへの副作用とする。
- CLIの内部関数、Pythonの内部結果型、解析ライブラリ、探索順、書き込み方式には依存しない。内部呼び出しをmockで置き換えない。
- 成功は終了コード0、失敗は非ゼロを確認し、仕様にない具体的な非ゼロ値を固定しない。
- 診断メッセージはstderrへ出力する。説明文の完全一致や罫線・色・JSONキー順は要求しない。
- 計測値の検証にはJSONを使用し、Console・Markdownの表示契約は別途検証する。
- 各行はケース群。列挙した条件はそれぞれ実行する。権限による失敗は実際のOS環境で再現し、不可能な環境では理由付きでスキップする。

## 計測仕様への適合性

入力・期待値の重複記載を避けるため[Python API側の計測ケース](../python_api/README.md#計測結果の契約と集計)を参照するが、CLIの出力も仕様由来の期待値と独立に照合する。

| ID | 種別 | 対象ケース群 | CLIから確認する内容 |
|---|---|---|---|
| CLI-M01 | 正常・境界 | API-M01〜M07 | 全指標の取得単位・集計項目、定義位置・包含関係、重複計上なし、重み付きの対象数での平均、0/null、メタデータ、成功分集計 |
| CLI-M02 | 正常・境界 | API-S01〜S10 | SLOC、関数長、関数・クラス数の全入力と集計値 |
| CLI-M03 | 正常・境界 | API-X01〜X16 | 構文別CC、確定しているCog、最大ネスト、独立関数の境界、非同期・メソッド |
| CLI-M04 | 正常・境界 | API-C01〜C15 | 依存先識別・重複排除・向き、CBO・Fan-out、未解決の区別、循環群と集計 |
| CLI-M05 | 正常・境界 | API-H01〜H15 | 対象メソッド、属性共有・呼び出し・property、独立グループ数、null除外集計 |
| CLI-M06 | 正常・境界・異常 | API-D01〜D15 | 49/50/51トークン、比較規則、出現独立性、重複SLOC集合、Scope率、部分解析 |

| CLI-C09 | 異常 | 比較可能0件、片側partial | 空結果でもpartialを出力後、非ゼロ終了 |
| CLI-C10 | 境界 | 未解決を含むが双方complete、CBO確定値3→2 | 差分-1と両側の未解決・不完全性を保持し、終了0 |

## 不正なコマンド指定

根拠：[CLI — Invalid Command Arguments](../../../docs/features/code-analysis/cli.md#invalid-command-arguments)。
各ケースは非ゼロ終了とstderrの診断を検証し、具体的な非ゼロ値・診断文言の完全一致は要求しない。

| ID | 種別 | 条件・操作 | 期待結果 |
|---|---|---|---|
| CLI-V01 | 異常 | 存在しないサブコマンド、両コマンドへの未知のオプションを指定する | 不正なコマンド指定として扱う |
| CLI-V02 | 異常 | analyzeのtarget不足、`--exclude`・`--format`・`--output`・結果入力オプションの値不足 | 必須の位置引数・オプション値の不足として扱う |
| CLI-V03 | 異常 | analyzeに2つ、compareに3つなど許可されていない余剰位置引数を渡す | 余剰引数を入力として黙って無視しない |
| CLI-V04 | 異常 | 両コマンドに未対応の`--format yaml`を指定する | 対応外形式として扱い、別形式で正常出力しない |

compareの入力不足・同一側への入力重複はCLI-P05、両側JSONと解析オプションの併用はCLI-PE04で検証する。

## インターフェース間の整合性

| ID | 種別 | 条件・操作 | 期待結果 |
|---|---|---|---|
| CLI-I01 | 結合 | 同じ入力・条件でCLIのJSONと公開APIの結果を取得する | 正常・空・partial・未解決の各入力で計測値と状態が一致する。仕様由来の期待値でもそれぞれを検証する |
| CLI-I02 | 結合 | 同じBefore・AfterをCLIと公開APIから比較する | 差分・変化率・比較不能・状態が一致する |

## 仕様確認後に期待値を確定するケース

| 項目 | 検証したいケース・未確定点 |

## 設計レビュー時の確認

- コマンドを実際に起動し、終了コード・stdout・stderr・保存結果をまとめて検証すること。
- 計測ケースの参照先にある各入力を実行し、ケース群名だけで検証済みにしないこと。
- 全形式×全出力先の基本動作と、状態に応じた終了規則の組み合わせを確認すること。
- 仕様が未確定の内容を、実装の現在の出力やスナップショットで正当化しないこと。
